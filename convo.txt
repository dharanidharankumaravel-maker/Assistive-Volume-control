1. PROJECT OVERVIEW & CORE PROMISE
--------------------------------------------------------------------------------
VolumePilot (com.volumepilot) is a production-grade, privacy-first, battery-efficient
Android application designed for users with broken hardware volume buttons, motor
accessibility needs, or single-handed mobility requirements.

Non-Negotiable Principles Adhered To:
- Reliability First: Persistent floating overlay survives app switches, orientation
  changes, and device reboot (Start on Boot).
- Privacy by Default: Zero ads, zero accounts, zero analytics SDKs, zero remote tracking,
  and strictly ZERO android.permission.INTERNET in the manifest or dependencies.
- Battery Efficiency: Pure event-driven architecture using Kotlin Flows, AudioManager
  callbacks, and Doze-aligned AlarmManager. Zero polling loops, zero CPU wake locks.
- Accessibility First: Full WCAG 2.1 Level AA compliance, 48dp+ touch targets, TalkBack
  custom accessibility actions, dynamic font scaling up to 200%.
- Anti-Deception: Zero misleading "volume booster" claims; includes a configurable
  decibel ceiling limiter (EnforceMaxVolumeCapUseCase) to protect hearing health.

6. FLOATING BUTTON DRAGGING & TOUCH INTERCEPTION FIX
--------------------------------------------------------------------------------
Problem:
- The floating volume bubble rendered on WindowManager was not draggable across the screen.
Root Cause:
- `overlayView.setOnTouchListener` was attached directly to `ComposeView`.
- In Android's ViewGroup touch hierarchy, `ComposeView`'s child (`AndroidComposeView`)
  consumed touches via `detectTapGestures`.
- Because `ComposeView` did not implement touch interception, `ViewGroup.dispatchTouchEvent`
  routed all `ACTION_MOVE` events directly to child views, bypassing `setOnTouchListener`.
Fix Implemented:
- Created `OverlayContainerView` (extending `FrameLayout`) hosting the `ComposeView`.
- Overrode `onInterceptTouchEvent`:
  - When collapsed: intercepts touch stream whenever movement exceeds system `touchSlop`
    (`abs(dx) > touchSlop || abs(dy) > touchSlop`), sending `ACTION_CANCEL` to Compose
    (cancelling pending tap/long-press gestures) and routing all subsequent `ACTION_MOVE`
    and `ACTION_UP` events directly into `onTouchEvent`.
  - When expanded: returns `false` so the expanded volume panel sliders, tabs, and buttons
    receive unhindered touch events without window dragging.
- In `onTouchEvent`:
  - Calculates movement delta using `rawX` and `rawY` (absolute digitizer coordinates) to
    prevent coordinate jitter during window relocation.
  - Updates `windowManager.updateViewLayout` in real-time.
  - On `ACTION_UP`, runs a 200ms `ValueAnimator` with `DecelerateInterpolator` to smoothly
    snap magnetically to the nearest screen edge (left or right, 16dp margin), and persists
    the new `OverlayPosition` to `UserSettings`.
- Preserves TalkBack accessibility (`Role.Button`, `onClick`, `customActions`) and Compose gestures.
- Verified: All 47 unit tests pass, and debug/release APKs build cleanly.

    3. Extracted foreground transparency matte and calibrated the assistive volume widget (slider + 3 buttons) to fit 100% within the 66dp safe zone (52dp height out of 108dp canvas).
    4. Generated complete set of density-specific adaptive foregrounds (`ic_launcher_foreground.png` for mdpi, hdpi, xhdpi, xxhdpi, xxxhdpi).
    5. Generated legacy square (`ic_launcher.png`) and round (`ic_launcher_round.png`) icons with gradient bleed and antialiased edges across all densities.
    6. Added Android 13+ themed icon support (`<monochrome>`) in both `ic_launcher.xml` and `ic_launcher_round.xml`.
    7. Separated notification icon to `res/drawable/ic_notification.xml` to avoid collision with launcher foreground.
